# Need and Benefits

Why orgs move to virtualization + cloud, and what they gain.

## Need (the problems it solves)
- Servers sat **idle** — 10-15% utilization, rest wasted.
- Buying hardware = huge upfront cost (**CapEx**), plus space, power, cooling.
- Scaling was slow — order server, wait weeks, install.
- Over-provisioning (buy for peak load) → money wasted most of the year.
- DR (disaster recovery) and backup were hard and manual.

## Benefits — Virtualization
- **Server consolidation** — many VMs on one box → fewer physical servers.
- **Better hardware utilization** — idle capacity put to use.
- **Isolation** — one VM crash/malware does not affect others.
- **Fast provisioning** — clone a VM in minutes, not days.
- **Snapshots** — save VM state, roll back on failure.
- **Easy migration** — move a running VM to another host (live migration).
- **Cost saving** — less hardware, power, cooling, floor space.
- Test/dev — run many OS/versions on one laptop.

## Benefits — Cloud (imp)
- **No upfront cost** — CapEx → **OpEx**, pay-as-you-go.
- **Elasticity / scalability** — scale up on Diwali sale, scale down after.
- **Global reach** — deploy near users, low latency.
- **Reliability** — provider gives redundancy, high availability, SLA.
- **Automatic updates** — provider patches infra.
- **Disaster recovery** — data replicated across regions.
- **Focus on business** — no data-centre babysitting.
- **Accessibility** — access from anywhere over internet.

## CapEx vs OpEx (short)
- **CapEx** = buy assets upfront (own servers).
- **OpEx** = pay ongoing for use (rent cloud).
- Cloud shifts CapEx → OpEx. *(imp line)*

## Drawbacks (be fair — often a sub-question)
- Needs constant internet.
- Data security / privacy concerns — data with third party.
- Vendor lock-in.
- Downtime if provider fails.
- Hidden / recurring costs if not monitored.
